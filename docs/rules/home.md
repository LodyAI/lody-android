# Home (Android)

Read before changing Home: the Chats list, grouping, families, the project index, the bottom bar or the hidden Projects tab. These rules bind every caller of the area, not only files in its directory.

- `home/HomeActivity` is the launcher: native sign-in without an account, otherwise `home/ChatListScreen`, which opens `chat/ChatScreen` for a row. It reads `AccountController` / `CatalogRepository` state only and picks the first workspace when none is restored.

- Layout matches iOS Home: Chats tab has the workspace capsule (logo + name) leading (its switcher menu is 200–260 dp wide and keeps each workspace name on one line, fading at the trailing edge via `LodyFadingText`, as iOS `WorkspaceSwitcherPanel`), search and the view menu sharing one trailing capsule, and `HomeSyncPill` floating centred over the bar for syncing / offline / briefly connected (web `MobileConnectionStatus`). All three bar capsules are 44 dp tall on `bgOverlay` with a `borderSubtle` outline and a small shadow. The workspace capsule uses the bar avatar (32 dp), hugs its name, and ellipsizes only at the bar's remaining width (bar width − 192 dp, iOS `InboxChrome.layout`), leaving the rest of the leading side to it; the pill uses callout text with 16 dp side padding (iOS `HomeSyncPill`). While the pill is visible the capsule collapses to its circular logo and restores its name when the pill leaves (iOS `InboxChrome.syncShown`); search takes over the bar and hides the capsule. A floating bar holds labelled Chats / Schedules / Settings tabs plus a separate create button. Schedules keeps the Chats header without the view menu; Settings shows account, workspace switching and sign-out. The Projects tab is hidden for now: its sources (`ProjectCards`, `ProjectAddSheets`, `ProjectAdding`) and the composables in `ChatListScreen` stay for its return, but nothing wires them.

- The view menu scopes Chats to My tasks (catalog session `userId` equals the signed-in user; `HomeScope`, SharedPreferences, default My tasks; search is unscoped). Chats follow the view menu's single grouping choice (`HomeGrouping`, SharedPreferences, default status) via `ChatListModel.home`: time buckets (last message, else `createdAt`), projects by latest activity (rows drop the project from line 2), or the Status view (Focus / Later / Settled). The Status view lists the runtime's catalog `statusView` layout (`mine` for My tasks, `team` otherwise) exactly as given; the runtime scopes My tasks per conversation (desktop `isSessionInMyScope`), while the native time and project groups below keep complete matching families; native code never sorts or classifies those rows, and without a layout (an older runtime or cache) the Status choice lists by time. Focus always lists, Later and Settled only when nonempty; tier labels show their counts, Later and Settled start collapsed (the stored `CollapsedGroups` set records changes from each group's default), Settled folds after 20 roots, a Later row shows its wake-up countdown (`3d`, `2h`, `45m`, `<1m`) after its status marks, and unread and activity time come from the layout row, so a woken conversation stays unread until read. Time and project groups are newest activity first; there is no separate sort. Outside search, tapping a group label collapses or expands its group, as on iOS: a trailing chevron points down while open and right when collapsed, rotating while rows animate (`animateItem`; `CollapsedGroups`, SharedPreferences, archived buckets kept separately); collapsed groups keep their label and project-index destination. Search stays by time. Outside search, Compose `stickyHeader` keeps a single accessible group label under the app bar; the next group pushes it off. Headers use the page colour without blur or a separate overlay. Search labels scroll normally. Rows use the F tree layout and start on one line: every root row keeps a 16 dp tree column so its title starts at 32 dp, and a child steps in 16 more (title at 48, callout). The trailing marks run the status (failed > waiting > working > unread), then the PR mark (only when no second line carries it) or the age, or the Later countdown in place of the age; a status mark takes the age's spot, as on iOS, and the owner avatar follows, 8 dp apart. Type follows the iOS `ChatRowContent`: 16 sp root titles (medium when unread), 15 sp children that go semibold when unread, and a 13 sp detail line and age; group labels use the iOS `groupLabel` (16 sp / 22 medium in tertiary ink). The optional second line appears only when someone opts into Project or Branch and shows repo / folder + project and branch, with the PR mark trailing, so the title line keeps the status and age; open / draft PRs carry the web CI verdict badge. Opened chats nest one level under their root opener within each group (`ChatListModel.nest`, mirroring iOS `SessionRows.tree`; contained Tabs keep their own row). The opener row carries the fold target on its tree column: a 32 dp wide, full-row-height target (16 dp chevron) that borrows all 16 dp of the screen margin, so the chevron centres on the trunk at x=20 and the target ends exactly where the title starts at 32 dp (`FoldedOpeners`, default unfolded; `ChatListModel.fold`). Folded, the children are hidden, the chevron points right and the opener's trailing end carries only the most urgent child status. Expanded, the chevron points down and the trunk (`drawFamilyTrunk`) runs from under it through the children, each curving into its title (`drawRail`, x=20 to x=40; only intermediate children continue the trunk past their midpoint). Children use 40 dp rows (the iOS `controlMd`; a second line grows the row to 56) with no gap between them. The last child adds a small (8 dp) bottom margin so the family reads apart from the next conversation. Children hide a project that repeats their opener's. The opener keeps its own status; folded, the child status follows it without replacing it. The view menu is a multi-select of those details (`ChatRowDetails`, SharedPreferences, default PR only); none leaves rows one line. Optional catalog fields (repo, branch, read / message / awaiting times, PRs) are parsed leniently in `runtime/CatalogJson` so older caches still load. `ChatListModel.groups` (pinned, projects by name, unassigned last) feeds the Projects tab. Keep the model pure and covered by `ChatListModelTest`.

- A first-run guide (`HomeOnboarding`, web `MobileHomeOnboarding`) replaces the Chats list only when the loaded catalog snapshot has no computers and no chats, archived included, and neither search nor the Archived view is on; it never appears while the snapshot is still loading. It offers the installer command and the localized desktop download link through copy and the Android share sheet only, and the phone never opens the download page.

- Every Home grouping (time/project/status) starts with the Pinned area. With a layout it is the layout's pin sections in their order: the default "Pinned" section only while it holds rows (or rows the scope hid), then every named section, each naming the rows the scope hid; the remaining groups exclude those families. Without a layout it is a single Pinned group of pinned families, newest first, when nonempty. Partition whole visible families before bucketing, so pinned families appear once and retain child folding. Project conversation lists use the same projection; archived chats and hidden Tabs never enter Pinned.

- Status view actions run through runtime `statusViewCommand` (`RuntimeCommand.StatusView`, the shared planner's command union, with the `mine` / `team` list the gesture happened in), never retried; a failure or zero writes (refused or nothing to change) is reported and a held drop reverts. Rows act only as their layout row allows (`canManage` for Later / Settle / Move to Focus and Focus order, `canPrefer` for pins and pin placement); section management follows the layout's `canManageSections` once `sectionsLoaded`. The runtime starts with `workspaceReadOnly` from the cached member list's own role (no owner, admin or member role); because a role read later only reaches the runtime at its next start, Home and the conversation page dismiss open Status or section controls when the live member list makes the member read-only. A second write in a multi-step action checks the current role before it starts.

- A long press opens the row menu: Later (also on Later rows, to re-set the wake-up), Settle or Move to Focus, Pin / Unpin, Move to section (every pin section, the default included, and New section…, which then moves the row there), Move to top and Archive. Moving while still pressed turns it into a drag (Calvin-LL Reorderable, whose `onMove` updates the held list synchronously) that reorders Focus, reorders and moves pinned rows between sections, pins a row dropped in the Pinned area and restores a Later or Settled row dropped in Focus. Each family is one list item. Headers and an empty Focus's landing slot are drop targets that never move. A drop onto a header lands at the top of its section, including when the section is collapsed. The drag detector tells a release from a cancel. Back and loss of window focus cancel an active drag even when Android still delivers a release. A cancel never writes or opens the menu, and a press that moved past touch slop opens no menu. The list scrolls at its edges; lift and each crossed slot give haptic feedback. `StatusMoves` names the root a row lands before (null is the end), never an index or key; drops elsewhere snap back. The dropped order holds until the catalog shows the row where it landed, or two catalogs after the write did not; incoming catalogs are frozen during a drag. TalkBack rows offer Move up / Move down and the menu as custom actions.

- A trailing swipe reveals Settle and Later on Focus and Later rows and both Focus and Archive on Settled rows, a leading swipe Pin or Unpin (reveal, then tap). Opened children move with their opener but take the same menu and swipes; a child the layout carries under a pinned opener is not pinned itself, so its own snooze / settle metadata decides Settle and Move to Focus. Later opens a bottom sheet with the runtime's four `snoozePresets` and their resolved times, and a custom date and time in the same sheet that refuses past times. Later, Settle and Move to Focus on a conversation with opened sub-conversations at any depth and in any tier (`ChatListModel.openedTree`) first ask whether they follow. Settle and Later confirm with an Undo that restores each affected session as it was before (`ChatListModel.restore`: a future snooze again, an explicit settle again, otherwise Focus); a woken row's float at the top of Focus is not restored. A pin section header's ⋯ menu is centred on the label without adding height, so labels with and without it keep the same spacing (`ControlBoundsTest`); it offers New section, and for named sections Rename, Move up, Move down and Delete (with a confirmation; its conversations stay pinned). The conversation page's More menu groups Later, Settle and Move to Focus into a Conversation status submenu above Close current conversation for its conversation's layout row (a Tab resolves to its conversation) through the same host (`rememberStatusActions`).

- A Later row shows its wake-up countdown after any status mark, formatted as the shared `formatSnoozeCountdown`. Countdowns, the custom wake-up check and read receipts use `StatusClock`, the server clock of the latest live catalog's `statusView.nowMs` (device clock until one arrives; cached catalogs never set it). The network runtime calibrates that clock with one exact credential-free `GET <worker>/api/time` ([network gates](auth-network.md)). A chat created on this phone shows at the top of Focus until the layout lists it, without status actions.

- Opening a conversation in the foreground, while the catalog is live, sends read receipts through runtime `markSessionRead` (`ChatListModel.readReceipts`, read from the remote catalog, not Tab watermarks): the opened session up to its last message or its expired snooze, whichever is later, and for a Tab also its conversation up to that conversation's expired snooze. A chat without messages or wake-up owes none. A receipt that failed while connecting is sent again once the catalog is live.

- The Chats view menu ends with an Archived switch (iOS `HomeArchive`, #2541 / #2563), held in memory so every launch opens on open chats. While on, the Chats list and its search show only archived chats in activity buckets (`ChatListModel.home(archived = true)`, honouring My tasks; no Pinned group, no project index), the page uses `bgArchived` with titles in tertiary ink, and a loaded catalog without archived chats reads "No archived chats". Settings has no Archived entry. Every Chats and search row opens its conversation on tap; a long press offers the row menu above (search rows and opened children: Archive only), or Unarchive only (no pin or status action) while the list shows archived chats. Either runs runtime `archiveSession` (`RuntimeCommand.ArchiveSession`, bridged in `runtime/src/network.mjs`) once, never retried, and reports the result or the failure in a snackbar; the catalog then moves the row between the open and archived lists.

- Home builds complete parent families before time/status/project bucketing. Tabs and side chats (`parentSessionId`) belong to their conversation and never list, as web `sessionListAtom` (iOS `SessionRows.isTab`, Android `ChatListModel.isTab`; Projects counts skip them too). Families come only from openedBySessionId, then openedByRootSessionId, against visible sessions, an opener that is a Tab resolving to its conversation; do not require matching projects. Only the parent determines the bucket; every descendant stays adjacent under that root. Missing/archived parents and cyclic references must not hide rows. My tasks preserves complete matching families; idle limits count roots and never split a family. Cross-project children keep their project label, and child urgency remains separate from the parent status.

- The opener's fold chevron expands and folds its children, tapped directly or through the opener's TalkBack action; the opener row's own tap opens the conversation. The folded row's most urgent child status sits in the opener's trailing marks, never as a separate line.

- A parent chat retains its own conversation status, including internal Tabs. When its children are folded, show the most urgent child status in the trailing marks; never replace the parent status with a child status.

- Conversation list attention includes its non-archived internal Tabs on the same
  machine, with failed, waiting, running, then unread priority. Side-panel sessions
  and independently opened chats do not contribute. Closed Tabs still contribute
  active status but not unread. Preserve Tab inputs through owner filters, keep
  Tabs hidden as list entries, and apply the summary to status grouping as well as
  row markers without rewriting catalog session state.

- Conversation lists show a compact circular owner avatar after the trailing status, PR mark and age (including children), in My tasks and Team tasks alike, resolved from the workspace member cache with a name-initial fallback when the member has no picture (a member missing from the cache shows no avatar); special status stays trailing. Titles and project details share the leading edge.

- The Chats project index is enabled only for project grouping with multiple sections and scrollable content. Scrolling reveals a solid icon capsule over the full-width list; it lingers for 800 ms (or the system accessibility timeout) after scrolling or direct interaction ends. Use a short slide transition without fading the opaque surface; remove pointer and accessibility targets as exit begins, and keep targets at least 48 dp apart. Use bounded landmarks when all sections do not fit; taps select the displayed section, scrubs stay anchored through touch slop and can reach every section, and accessibility range actions expose omitted sections. Only the visible capsule accepts taps and scrubs, with no long-press activation or hidden rail. Scrubbing targets rendered headers after family folding. Backgrounding, disposal or unavailable scrolling dismisses the index and cancels pending jumps. Project icons prefer catalog repository identity through the existing image cache, with repository/monogram fallbacks.

- The Chats bottom bar collapses after a user scroll passes the shared spacing threshold: hide tab labels and inactive tabs, contract the capsule toward the leading edge to show only the active icon, and shrink the separate create button. Keep it compact while scrolling back; restore only at the list top. Other tabs use the expanded bar. Retain accessibility labels and stable bottom content insets during the animation.

- Projects tab, while hidden (iOS `ProjectsListController`), restores as follows: the Chats header (`HomeTopBar` with workspace capsule, sync pill, search and its own `ProjectsViewMenu`) and no title; `ProjectCards.build` cards (`ProjectCardView`, `bgSunken`), newest activity first, showing a 40 dp logo centred on both lines (GitHub owner avatar, else the name's initial), the name (`Owner/Repo`), the compact age, the computer (local) or GitHub, and the most pressing open-chat state by `ProjectCards.pressing` (needs you, running, just finished, open PRs, else the count; a card summary only, never a Home grouping). Search filters the cards in place; the view menu holds the shared scope, the source (`ProjectSource`) and hiding projects without open chats (`ProjectViewPrefs`). A project without chats still opens to its empty list.

- On Schedules the create button turns into "+" (`HomeBottomBar(adds)`) and opens a new schedule. A restored Projects tab's "+" toggles `ProjectAddMenu` (two capsules springing up from it over a scrim; Back / scrim fold them). `ProjectAdding` (`LiveProjectAdding`, `LodyApplication.projectAdding`) does the work: local folders through the shared runtime's `localProjects` (bridged as `RuntimeCommand.LocalProjects`: machines, browse, add, cancel), GitHub repositories through Convex with the verified account, as iOS `WorkspaceSettingsCloud` (`github:listWorkspaceReposWithStatus`, `github:setRepoEnabled` for admins / owners with a read back, `github:createGitHubInstallState` → the App's install page). `LocalFolderSheet` picks the computer (skipped when one), browses from home with an up button and a typed path, and adds the open folder; `GitHubRepoSheet` searches the repositories, not-yet-added first.
