# Settings (Android)

Read before changing Settings. These rules bind every caller of the area, not only files in its directory.

- Settings Home uses iOS flat groups without Machines or Agent conversation sync; Preferences, Agents, Roles and shortcuts follow [Settings](../../README.md#settings). Optimistic changes roll back on failure. Writes require fresh owner/online permission, preserve conflict bases, and never replay uncertain outcomes. Filter catalog agentUsage by runtime eligibility and provider/config identity; reuse session quota window names and reset captions. Other destinations remain explicit placeholders. Credential drafts remain write-only and ephemeral; never persist or log them.

- GitHub Settings and Add Project share a fresh personal-operation authorization preflight before requesting installation state. Missing or expired grants offer Web settings through the configured backend’s neutral installation callback; the user signs into the same Lody account, authorizes, then returns and retries. Failed or malformed reads remain retryable errors, never missing-grant claims. Keep the existing live role checks and final server authorization, and do not change the personal operation preference.

- The Agents page keeps the machine selector above the selected machine's providers. Each provider row shows its icon, name, kind and, when quota is reported, one compact quota line with the two tightest windows by remaining percent (plus `+N`); remaining at or below 20% uses the warning colour. Tapping the line opens the provider's quota sheet, which also offers Refresh usage when the provider advertises `rate-limits-refresh` and the user can manage its online machine. There is no separate usage section.

- The provider editor orders a header card (icon, name, machine and presence, quota line, refresh status), Basics, Command (Custom only), Account, Conversation defaults, Environment variables and Delete. Every editable value is a tappable label/value row; text is edited in a bottom sheet with Cancel/Done that changes only the draft, and Save persists it. Save and the More menu (Refresh models and modes, Test connection, Delete) are hidden for read-only providers or machines. Description, runtime executable paths, binary status/install and the Pi extension scan are not shown; their loaded values are sent back unchanged on save.
